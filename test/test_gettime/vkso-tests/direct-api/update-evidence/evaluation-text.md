# UPDATE evaluation 正文候选

在本次插桩配置下，VKSO 发布均值随受测读取负载的变化范围小于 Raw。我们分别在 idle 和三个公开 `clock_gettime` 读者负载下测量周期 `timekeeping_update` 的函数内发布区间，每个配置和后端运行四次独立启动。每次启动对每种负载采集十五个 15 秒窗口，统计包含全部 3,599,774 次周期发布。主结果使用完整样本均值，先在启动内汇总，再对四次启动等权平均。计时覆盖已持锁的函数内发布路径，不包含锁等待、此前推进计算，以及调用者在函数外执行的序列开始、正式 timekeeper 复制和最终序列提交。四个正式镜像中，函数返回后 Raw 复制 280 字节、VKSO 复制 264 字节；这些操作未被现有时间戳覆盖，不能由本表推算整个周期发布成本。两组配置分别记为 Normal（CONFIG_RETPOLINE=y）和 no-retpoline；它们同时包含返回跳板等缓解选项的差异，组间比较反映整组配置的影响。

Normal 配置下，VKSO 四种负载的发布均值为 121.649～122.528 TSC ticks，变动范围为 0.878 ticks；Raw 为 116.718～132.303 ticks，变动范围为 15.585 ticks。no-retpoline 下，相应范围为 VKSO 124.333～126.416、Raw 114.779～132.623 ticks。在同一次启动内比较读者负载相对 idle 的变化，VKSO 的增量在全部六项配置/负载对照的四个启动块中均小于 Raw。

在 MONOTONIC_RAW 和 MONOTONIC_COARSE 读者存在时，VKSO 在该函数内计时区间的完整样本均值较低。Normal 下分别降低 9.775 和 10.521 ticks，对应 7.39% 和 7.96%；no-retpoline 下分别降低 6.730 和 6.914 ticks，对应 5.12% 和 5.21%，四个启动块方向一致。idle 下 VKSO 分别增加 5.438 和 9.554 ticks，MONOTONIC 下的差值为 −0.642 和 +2.965 ticks。因此，指定测量方案下的后端成本差随读取负载变化。

分布分解进一步说明了整体成本如何形成。按各分布谷值划分低、高侧后，八项对照的低侧成本贡献均降低，而更高的高侧占比产生正向成本贡献。我们将超过 300 ticks 的超额部分单列，并在每个启动块中精确还原完整均值差。低侧成本贡献为 −16.043～−5.159 ticks，占比贡献为 +5.757～+14.945 ticks；300-tick 超额尾部贡献为 −1.627～−0.075 ticks。谷值移动和平滑宽度变化下，可解析分布的低侧收益与占比代价方向保持一致。完整均值的变化来自这些分布项的合成，低峰位置或高侧占比均不能单独代表总成本。

记录器对照表明，上述相对成本依赖测量实现。我们固定功能版本，在两后端、两组缓解配置和两种记录器下各运行两次独立启动，共获得 383,958 个周期样本。从旧记录器切换到当前记录器后，VKSO−Raw 完整均值差的变化在 Normal 下为 +0.150～+11.951 ticks，在 no-retpoline 下为 +20.793～+31.027 ticks，范围取决于读取负载。记录写入发生在结束时间戳之后，但它仍可能通过代码生成、布局及前序记录行为影响测量。该结果表明，测量扰动不能作为两后端共同的常数抵消。

进一步的干预检验了调用接口、额外检查和特定元数据布局的解释。在 no-retpoline 下，当前调用接口配合旧记录器主体的两次启动共取得 47,998 个样本，八个启动与负载组合的主高峰均为 125～128 ticks，没有复现当前记录器约 146～148 ticks 的持续主峰移动；其中两个单独窗口仍出现 147 ticks 主峰。在当前镜像内固定代码与状态地址，仅将计时结束后的额外标记比较和条件跳转替换为等长 NOP，一次启动、两个负载的八个平衡块主高峰差为 −5～0 ticks。

随后在同一次启动内保留上述检查，仅改变记录计数与样本指针是否位于同一 64 字节对齐区域，在两个地址位置、两个负载下取得 83,998 个周期样本。原版及迁移参照均复现 140～155 ticks 主高峰，十六个块级布局对照的峰移为 −5～+5 ticks，未达到预定的同向且各至少 10 ticks 的重复筛选条件。完整均值、占比和尾部仍有变化，四组对照的逐块均值差均出现方向变化。主分析保留一条 CPU 2 发布记录，CPU 0 子集敏感性不改变峰位及停止决定。guard 与布局干预来自同一次启动，分别按预定规则停止同类追加。这些结果尚未将历史约 20 ticks 的持续峰移归结到接口、额外检查或所测计数/指针地址关系中的单一因素；其他代码和状态布局及其交互仍未排除。

最后，我们在当前记录入口放回旧记录主体，保留当前状态与样本缓冲地址，以进一步区分记录主体和整体链接布局。36 个窗口共取得 71,996 个周期样本，原版参照主峰复现，八个块级主峰差为 −3～+3 ticks，全部旧主体窗口主峰仍在 145～151 ticks。idle 和 monotonic 的完整均值分别下降 3.528 和 7.027 ticks，其中占比项贡献 −3.974 和 −5.547 ticks；两负载的逐块均值差均有方向变化。该先导也未达到预定重复门槛。三个固定镜像干预来自同一次启动，其结果限制了各受测因素单独复现历史峰移的解释，仍未排除其他代码/状态布局及交互。

成本分解解释了完整均值如何由条件成本、占比和尾部组成，多峰对应的物理机制仍未识别。记录器对照采用历史独立启动而非同期随机配对，正式采集中另有已记录的后台服务重启活动。因此，正式 UPDATE 数值描述指定插桩和运行条件下的成本与负载响应，不用于估计无插桩实现的固有成本。

Normal的四种负载中，记录器切换引起的后端均值差变化在两块均为负。no-retpoline下，idle和MONOTONIC_RAW两块为负，MONOTONIC两块为正，MONOTONIC_COARSE则从+43.365变为−44.996 ticks。尤其MONOTONIC在两组缓解配置中的响应方向相反，说明记录器影响不能用跨配置的共同常数抵消。no-retpoline COARSE两块平均变化为−0.816 ticks，平均值接近零仍包含方向相反的两块响应。两配置在不同时段采集，且包含多个缓解选项，组间差异不单独归因于retpoline。这些完整发布结果与前述函数内结果具有不同的计时范围。

峰位和均值对记录器切换的响应也不同。以σ=3 ticks平滑直方图定位最高局部峰，no-retpoline COARSE的后端峰位差在切换记录器后分别增加82和81 ticks，完整均值差的变化却发生方向翻转。按各单元自身的样本秩分解完整均值，最低90%样本对这一变化的贡献分别为+43.498和−40.273 ticks，最高1%的贡献为+15.531和−5.723 ticks。因此，翻转涉及常见样本的分布变化，并非只来自极端尾部。

Normal中的分布分解同样显示了主体和尾部的不同作用。MONOTONIC_RAW两块最低90%的记录器效应贡献分别为−84.707和−69.346 ticks，最高1%分别贡献+6.326和+5.509 ticks；MONOTONIC_COARSE对应为−65.762和−79.154，以及+14.145和+13.533 ticks。两种负载的尾部均抵消了一部分负向均值变化。各共同时间区域的占比、条件均值和对完整均值的贡献分别报告，区域不对应已识别的硬件状态。

Normal COARSE还体现出主峰身份选择的敏感性。第一块在σ=2、3、5 ticks时，记录器切换造成的后端峰位差变化分别为+187、+186、+53 ticks，第二块为+53、+53、+51 ticks。Current Raw两次启动的完整均值仅相差3.086 ticks，但σ=3下最高局部峰从641切换到773 ticks；σ=5下则为775和774 ticks。这里不能把主峰切换解释为同一物理峰移动132 ticks。完整均值、时间区域占比和主峰位置描述分布的不同方面。[两配置完整分布与对照](../../update-bench/mechanism-evidence/full-publication-two-configurations/README.md)

起始计时块的位置控制没有复现持续的大幅峰移。我们在同一Current VKSO no-retpoline启动中保留原版起点，并将相同指令种类和次序的计时块分别搬移到同一代码页内模64偏移为6和60的位置，两者返回同一发布入口。搬移模式较原版增加一个计时前的直接跳转，发布代码和状态地址保持不动。该实验包含idle和MONOTONIC_COARSE两种负载、六个平衡三模式块以及装载前后参照，共40个8秒窗口、79,992次周期发布；它与上述矩阵中的一次Current VKSO运行属于同一启动。

在σ=2、3和5 ticks三种平滑宽度下，不同偏移搬移相对同偏移搬移的逐块主峰差为−2～+1 ticks。两种负载的合并完整均值差分别为−2.537和+7.999 ticks，逐块方向均有变化。COARSE第六块中，同偏移搬移与原版的完整经验CDF距离为0.1185，超过预定的0.10参照门槛，因此该负载未完全保持原分布。结果限制了这一位置因素单独复现持续大幅峰移的解释，同时保留了均值和尾部变化；其他代码和状态布局及其交互尚未被这一控制识别。

读取速率控制进一步显示，主峰近似不动时完整发布成本仍会变化。在Current no-retpoline镜像上，我们对完整MONOTONIC_COARSE公开API读取器设置400和1600 ticks两档目标间隔，两后端各一次启动，共取得40窗、80,000个周期样本。快档实际调用率约为目标的75.5%，低于预定80%下限；慢档为88.7%～89.3%。在这些实际达到的速率下，慢档相对快档的四块完整均值变化为Raw −84.353～−65.346、VKSO −19.210～−12.802 ticks，三个平滑宽度下的主峰变化均仅−1～0 ticks。新读取框架还增加了逐调用计时、等待和记账，其不节流模式与原读取器的发布分布也有差异。因此，这些结果描述实际读取活动改变时的分布响应，尚不能单独归因于共享缓存行访问频率。VKSO与前述位置控制共用一次启动，窗口块不增加独立启动数。[读取速率与分布](../../update-bench/mechanism-evidence/reader-cadence-paired-boot1-review/interpretation.md)

计时排序对照检验了时间戳执行顺序和写入完成对成本的影响。两后端各一次启动，在idle和MONOTONIC_COARSE下取得88窗、176,000个周期样本；Raw与读取速率控制共用一次启动。在固定的两个搬移计时块中，我们先在两个RDTSCP之后加入LFENCE，再切换终点RDTSCP之前的MFENCE。终点MFENCE使Raw的四块均值增加170.1830～180.2475 ticks（idle）和116.2525～198.2980 ticks（COARSE），VKSO分别增加157.6865～223.3570和131.4455～213.4040 ticks。VKSO减Raw的屏障响应差在两个负载中均有块间方向变化，不能作为可抵消的公共常数。

这一排序实验的搬移参照也改变了原始分布。两后端、两负载均未在全部四块同时保持预定的CDF距离不超过0.10及主峰差不超过5 ticks。因而，屏障响应说明搬移环境中的计时方式会影响成本，尚不能识别原位自然多峰的物理根因，也不能作为原始样本的事后成本修正。屏障自身及其对前序存储完成状态的影响均包含在上述响应中。[计时排序对照](../../update-bench/mechanism-evidence/publication-ordering-paired-boot1-review/interpretation.md)

Normal镜像的实际返回指令还受启动时地址相关改写影响。我们在当前VKSO镜像上原位切换两个发布返回位点，将每次发布中的三个ITS跳板返回改为本地返回，保持函数布局、其余字节、计时和记录器不变。在与完整矩阵共用的一次启动中，四负载、四个交错块及装载前后参照共提供40窗、79,997个样本。三个平滑宽度下，逐块主峰差均为−1～+1 tick，没有持续的同区域占比响应；各负载完整均值差均有方向反转。idle和COARSE参照保持，MONOTONIC和RAW的部分参照存在漂移。这项结果未支持用所测三个返回跳转解释持续峰移；编译缓解选项也不能直接换算为运行时的固定成本。[原位返回路由控制](../../update-bench/mechanism-evidence/publication-return-normal-boot1-review/interpretation.md)

no-retpoline采集配置和已监控后台服务的归档核对未找到COARSE记录器效应翻转的唯一原因。去掉每窗开头5%或10%的样本后，两块效应仍一正一负；读取器也只在停止后输出批次记录。这限制了仅用窗口起始瞬态或采集中逐批输出解释变化的说法。当前证据表明，完整发布的后端成本差依赖记录器及运行条件；自然多峰、后端占比差和配置间峰位差仍需物理机制证据。两配置的完整发布矩阵均显示测量实现会改变后端比较，所测数值描述对应插桩和运行条件下的成本。
