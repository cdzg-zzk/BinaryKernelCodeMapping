# VKSO Reader 性能实验报告

## 1. 报告范围

本报告评估当前紧凑实现 VKSO 的 reader 性能，回答三个问题：

1. 当前 VKSO 与同轮 raw vDSO 相比是快还是慢；
2. 当前 VKSO 相比优化前版本是否确实得到改善；
3. 差异来自 reader 核心、fallback、syscall、重试协议还是编译防护选项。

当前主实验：

- `run_id`：`20260728T090125Z-vkso-compact-read`
- 结果目录：`results/20260728T090125Z-vkso-compact-read`
- 当前 VKSO commit：`be35a28c983f754650c2ddb3312a4e29796a2194`
- 当前源码哈希：`df32187680ba910d98c58775fa8b119a1db5703e03fb9ef5c3ac6fc1422b1cb8`
- 优化前 reader 参照：`20260728T013904Z-vkso-final`
- 优化前 VKSO 包 commit：`9ad92a1`

这里将同一轮的 raw 结果作为主要性能基线，将 `013904` 作为跨版本优化参照。更早的 Base2 仅属于历史版本，不再与当前结果混为同一基线。

## 2. 核心结论

当前版本值得保留，reader 优化有效。

- Normal 配置下，20 个用户入口等权几何平均比 raw 快 `0.886%`；排除 3 个 syscall fallback 后，17 个直接用户态入口快 `1.053%`。
- No-retpoline 配置下，20 个入口与 raw 基本持平，仅慢 `0.189%`；17 个直接入口慢 `0.106%`。
- 与优化前 VKSO 相比，并使用各自同轮 raw 消除跨轮机器波动后：
  - Normal 的 20 个入口改善 `1.710%`，7 个主要 `clock_gettime` 改善 `2.544%`；
  - No-retpoline 的 20 个入口改善 `0.289%`，7 个主要 `clock_gettime` 改善 `2.387%`。
- 当前 VKSO 的 `time()` 比 raw 稳定快约 `5.5%`，coarse clock 也有明显收益。
- `gettimeofday()` 仍是最明确的剩余弱项，多数参数组合慢约 `1%–8%`。
- fallback 扣除同镜像 syscall 成本后并不比 raw 差，当前 wrapper 反而少约 `0–4 cycles`。完整 fallback 的小幅差异主要来自 syscall 本身的启动间波动。
- syscall 路径没有出现统一内核 core 导致的系统性退化：Normal 的 20 个 syscall 平均快 `1.963%`，No-retpoline 整体基本持平；7 个主要 clock syscall 在两种配置下都全部快于 raw。
- VKSO 每次高精度 seq 读取仍固定多约 `1 cycle`，但重试率降低 `94%–97%`。

需要谨慎解释总体平均数。Normal 的 20 项几何平均是 `-0.886%`，但 20 个逐接口百分比的中位数是 `+0.139%`；这说明收益集中在 coarse clock 和 `time()`，不能表述为“每个接口都更快”。

## 4. 统计口径

表中 cycles 是 31 轮结果的中位数。

差异定义为：

```text
delta% = (VKSO / raw - 1) × 100%
```

- 负值：VKSO 更快；
- 正值：VKSO 更慢。

分组汇总采用各接口比值的等权几何平均，防止高延迟 syscall 对低延迟用户态入口形成不合理权重。跨实验轮次比较时，再除以对应轮次 raw 的比值，以降低 CPU 状态、频率和代码布局漂移带来的影响。

## 6. 主要 reader 路径分析

### 6.1 高精度 clock_gettime

当前结果不是单向快或慢：

- `CLOCK_REALTIME`：两种配置均快 `2.10%`；
- `CLOCK_MONOTONIC_RAW`：快 `0.22%–0.89%`；
- `CLOCK_TAI`：快 `0.35%–0.64%`；
- `CLOCK_MONOTONIC`：慢 `1.24%–2.27%`；
- `CLOCK_BOOTTIME`：慢 `2.17%–3.10%`。

后两者仍需应用 MM_data 的 namespace offset。当前实现已消除旧版不必要的 MM_data/context 处理，但有偏移语义的 clock 仍比 root-namespace 可直接读取的 realtime 多固定工作。

### 6.2 coarse clock

coarse 路径是本轮优化最明显的收益之一：

- `CLOCK_MONOTONIC_COARSE` 快 `7.67%–11.46%`；
- `CLOCK_REALTIME_COARSE` 在 Normal 基本持平，在 No-ret 快 `7.35%`。

这类入口本身只有约 `15–18 cycles`，减少一两条依赖链或改善布局就会表现为较大的百分比。因此论文中应同时展示绝对 cycles，不能只展示百分比。

### 6.3 time

`time(NULL)` 和 `time(&value)` 均稳定快约 `5.5%`，绝对收益约 `1 cycle`。这说明紧凑 shared-data 读取和直接 wrapper 可以在极短路径上兑现收益。

### 6.4 gettimeofday

`gettimeofday` 是当前最明确的用户态弱项：

- 完整 `(tv,tz)` 在 Normal 基本持平，在 No-ret 快 `1.22%`；
- 仅 `tv` 慢 `1.45%–3.42%`；
- 仅 `tz` 慢约 `5.2%`；
- 两个参数都为 NULL 慢 `3.70%–7.52%`。

这些接口的绝对回退通常只有约 `0.2–1.3 cycles`。NULL 组合的 raw vDSO 极短，VKSO 的统一入口判断占比因而被放大。若继续优化 reader，应只针对这一组做有证据的布局或 wrapper 调整，不应重新增加全局 mode/context 层。

### 6.5 getcpu

Normal 下两种参数组合都与 raw 基本一致。No-ret 下 `(cpu,node)` 持平，而 `(NULL,NULL)` 慢约 `0.95 cycle`。这同样属于极短 NULL 快路径的固定成本问题。

## 8. Fallback 分析

只比较用户入口总耗时会把 syscall 内核执行时间也算进 fallback。为隔离 wrapper 固定成本，使用：

```text
fallback wrapper overhead = 用户入口 cycles - 同镜像显式 syscall cycles
```

| 路径 | Raw Normal | VKSO Normal | VKSO 额外成本 | Raw No-ret | VKSO No-ret | VKSO 额外成本 |
|---|---:|---:|---:|---:|---:|---:|
| clock_gettime process CPU | 13.868 | 10.463 | -3.405 | 12.916 | 12.914 | -0.003 |
| clock_gettime realtime alarm | 13.246 | 11.896 | -1.350 | 12.446 | 11.364 | -1.082 |
| clock_getres process CPU | 4.710 | 4.698 | -0.012 | 10.289 | 6.617 | -3.672 |

结论：当前 VKSO fallback wrapper 并不慢，额外成本与 raw 相同或低 `1–4 cycles`。因此不应再用大段专用 fallback 代码换取性能；既增加源码，也没有当前测量证据支持。

| 配置 | 协议 | Raw cycles | VKSO cycles | 固定差异 | Raw retries/百万 | VKSO retries/百万 | 重试变化 |

| Normal | hres | 43.1511 | 44.1537 | +1.0027 | 149.92 | 4.79 | -96.81% |
| Normal | raw | 43.1512 | 44.1534 | +1.0022 | 78.04 | 4.69 | -93.99% |

当前 VKSO 的协议固定成本比 raw 多约 `1 cycle`，但重试率显著更低。两者是独立现象：

- 固定 `1 cycle` 来自读取协议和依赖链；
- 重试减少来自 shared-data 发布窗口更短；
- 不应为了使重试率接近 raw 而人为扩大写侧临界区，这不会收回固定成本，只会同时伤害 reader 与并发行为。

## 11. 与优化前 VKSO 的比较

直接跨重启比较 cycles 容易受到 CPU 状态影响，因此使用：

```text
normalized improvement =
  (current VKSO / current raw) /
  (old VKSO / old raw) - 1
```

| 分组 | 当前/旧版直接变化 | raw 归一化后的改善 |
|---|---:|---:|
| Normal 7 clocks | -2.771% | -2.544% |
| Normal 17 direct | -3.697% | -1.775% |
| Normal all 20 | -3.338% | -1.710% |
| Normal 3 fallback | -1.278% | -1.344% |
| No-ret 7 clocks | -0.074% | -2.387% |
| No-ret 17 direct | -0.207% | -0.300% |
| No-ret all 20 | -0.183% | -0.289% |
| No-ret 3 fallback | -0.042% | -0.225% |

优化前后 raw 测量路径的 PMU 动态指令数和分支数完全一致，说明测试程序更新没有改变被计时 raw 路径的核心工作。但 raw cycles 的逐接口中位绝对漂移仍约为：

- Normal：`1.37%`；
- No-retpoline：`1.54%`。

因此 `0.1%–1%` 的跨轮差异只能作为趋势，`2%` 以上且 PMU 工作量同步下降的结果更可信。

### 11.1 当前修改减少的动态工作

当前 VKSO 相比优化前版本，在主要用户 reader 中：

- 大多数受支持 clock 减少约 `2` 条 retired instructions；
- coarse monotonic 减少 `3` 条指令和 `1` 个分支；
- process CPU fallback 减少约 `10–18` 条指令和 `2–4` 个分支；
- realtime alarm fallback 减少约 `11` 条指令和 `1` 个分支。

在 7 个 clock syscall 中，当前内核路径相比旧版通常减少：

- `2–13` 条 retired instructions；
- `1–5` 个 branches。

这证明显式 MM_data 参数和冷 context 检查的紧凑化确实减少了动态工作，而不是只靠偶然的 cycles 波动。

## 12. 当前实现的代码与二进制变化

本轮紧凑化主要做了三件事：

1. 将 MM_data 从通用 context/mode 间接描述改为 reader 所需的直接参数语义；
2. 将 cycles context 判断留在真正需要的冷路径，TSC 常用路径不重复支付；
3. 压缩 fallback wrapper，去除旧版不必要的 mode 传递和重复判断。

与优化前包相比：

| 项目 | 优化前 | 当前 | 变化 |
|---|---:|---:|---:|
| wrapper 主符号 | 153 B | 145 B | -8 B（-5.23%） |
| `vkso_fallback` | 48 B | 32 B | -16 B（-33.33%） |
| 共享 core 主符号 | 96 B | 96 B | 不变 |
| Normal `libkernel.so` 文件 | 23288 B | 23288 B | 不变 |
| No-ret `libkernel.so` 文件 | 19072 B | 19072 B | 不变 |

整个 ELF 文件大小未变是页对齐和 section padding 所致，不能据此否定热符号已经缩小。当前源码相对紧凑化起点总体为 `+64/-86`，净减少 `22` 行；其中生产 kernel 路径净减少约 `21` 行。

## 13. Retpoline、return thunk 与本轮结论

Normal 与 No-retpoline 不是简单的“有无 return thunk”：

- retpoline 主要影响间接调用/间接跳转防护；
- return thunk 影响函数返回；
- 两者是不同机制，必须从对应镜像 config 和反汇编确认，不能混称。

当前两种配置给出的主要结论一致：

- VKSO 不存在大范围 reader 退化；
- `time()` 和若干 clock 有稳定收益；
- `gettimeofday` NULL/单参数组合仍有固定成本；
- fallback wrapper 已不是主要问题；
- seq 固定多约 `1 cycle`，重试率显著下降。

因此本轮结论不依赖单一 thunk 配置。No-retpoline 结果用于隔离间接调用防护的影响，不应取代 Normal 作为系统默认配置结论。

## 14. Reader、update 与并发实验的关系

本报告只把 `090125` 四组 reader 数据作为当前版本的直接证据。

此前已经存在独立的：

- update-side 实验；
- read/update 并发实验。

但它们针对的是优化前实现。当前 `be35a28` 主要改变 reader 的 MM_data/cycles/fallback 组织，没有重新设计 writer 发布协议；理论上不应显著改变 update-side，但论文最终数据仍应使用当前 commit 重新确认，不能直接把旧 update 数值标成当前版本结果。

## 16. 最终判断

当前紧凑版本已经达到“功能完整、reader 总体不差、部分热路径更快、代码更紧凑”的阶段性目标：

- Normal 默认配置下总体优于同轮 raw；
- No-retpoline 下总体与 raw 等价；
- 主要 clock reader 的优化相对旧 VKSO 明确有效；
- syscall 共享 core 没有造成普遍性能损失；
- fallback 已经足够紧凑，不应继续用代码膨胀换取不确定收益；
- 剩余主要 reader 优化对象是 `gettimeofday` 的 NULL/单参数快路径，以及 monotonic/boottime 的约 `1–2 cycles` MM_data 固定成本。

论文中应采用“绝对 cycles + 百分比 + 胜出接口数 + PMU 工作量 + 功能矩阵”共同呈现。只写平均百分比会掩盖不同接口方向不一致，也无法说明当前优化为什么有效。
