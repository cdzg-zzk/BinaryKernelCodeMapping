# M05 阶段报告：纯 shared-time 读取 core

## 1. 阶段结果

M05 已将共享算法与执行环境、fallback 策略明确分层：

```text
public ABI wrapper
  ├─ typed global-time reader -> shared core -> cycles provider
  └─ cold failure             -> syscall / kernel backend
```

shared core 只读取 canonical shared state、执行 seq 协议、cycle delta、
mult/shift、base、namespace offset 与归一化。它不再包含 syscall 指令、
syscall number、`k_clock` 或 fallback mode。

内部状态固定为：

- `VKSO_TIME_OK`：共享算法完成读取；
- `VKSO_TIME_UNSUPPORTED_MODE`：当前 environment provider 不能读取该
  clock mode；
- `VKSO_TIME_BACKEND_REQUIRED`：clock ID 不属于 global-time shared core。

## 2. Core、provider 与 public policy

### Shared core

七种 global clock、`gettimeofday` 和 `clock_getres` 继续复用同一组 typed
reader 与换算原语。generic core 只做类型分派，typed 成功路径不进入 generic
dispatcher，也不读取 fallback 状态。

### Cycles provider

TSC 仍是编译期内联热路径；PVClock 与 Hyper-V 保持直接调用的冷 provider。
`struct vkso_context` 只保留两个 environment 地址，从 24 bytes 缩小到
16 bytes。`clock_getres` 不使用 cycles，因而彻底移除 context 参数。

### Public fallback

- 用户 `__vkso_clock_gettime`、`__vkso_clock_getres` 和
  `__vkso_gettimeofday` 各自拥有唯一 cold syscall 出口；
- kernel syscall dispatcher 对所有非 OK 状态统一进入现有 POSIX backend；
- pure core 不知道 syscall ABI，也不接触 `clockid_to_kclock()`。

这保留了 CPU、alarm、dynamic/PTP 与 invalid clock 的 Raw 语义，同时避免
shared 算法与任一 public 执行策略耦合。

## 3. Cycle delta 与 mask 语义

M05 恢复 ABI v11 中 `mask` 的实际消费：

- `mask == U64_MAX`：保持 x86 native vDSO 语义，轻微 backward cycle
  observation clamp 为零；
- finite mask：使用 `(cycles - cycle_last) & mask`，恢复通用
  clocksource wrap 语义。

这不是在热路径叠加两套算法：x86 TSC 的常见分支直接进入 subtraction/clamp，
finite-mask 分支仅为可表达的非 64-bit provider 保留。

`CONFIG_VKSO_TIME_TEST=y` 的启动期自检覆盖：

- forward delta：`105 - 100 = 5`；
- backward U64 TSC clamp：`95 - 100 = 0`；
- 8-bit wrap：`3 - 0xfe = 5`。

## 4. 代码量与静态路径

本阶段产品源码 diff 为 151 additions、117 deletions，其中：

- pure core：27 additions、61 deletions，净减少 34 行；
- internal/provider primitive：增加可审计的 mask helper 与状态传播；
- user entry：将 syscall policy 从共享 core 移到 ABI 边界；
- 测试：增加三种 cycle-delta 自检。

生产目标文件：

- `vkso_time_core.o` `.text`：2516 bytes；
- `vkso_time_cycles.o` `.text`：151 bytes；
- `libkernel.so`：text 16949 bytes、data 120 bytes；
- 相对 M04，`libkernel.so` data 从 128 bytes 降为 120 bytes；
- `vkso_fallback` 符号完全消失。

`libkernel.so` 的 syscall 只存在于 public wrapper 的 cold fallback label；
core 地址区间不含 syscall。M05 不据此声明真实性能变化，裸机结论留给 M10。

## 6. 退出判断

M05 退出条件满足：

- shared core 内无 syscall、`k_clock` 或 fallback mode；
- cycles provider 与换算原语分离；
- global-time、namespace、PV/HV 编译路径和 invalid-mode fallback 通过；
- mask wrap 与 x86 backward clamp 有独立运行时证据；
- 用户 syscall 与 kernel backend policy 均位于 public 边界。

下一阶段 M06 将只迁移 M01 审计为普通上下文安全的 `ktime_get_*` reader，
使其成为 root-namespace typed shared-core wrapper；fast/NMI、
writer-locked、early-boot 与 cross-timestamp 路径继续保持专用。
