# M07 阶段报告：统一 clock dispatcher 与 backend 边界

## 1. 阶段结果

M07 已将 native/compat `clock_gettime` 与 `clock_getres` 收敛到各自唯一的
内部 dispatcher：

```text
clock_gettime syscall
  -> vkso_clock_gettime_core()：一次 global clock 分类
     -> OK：直接 usercopy
     -> UNSUPPORTED_MODE：private timekeeper 冷路径
     -> BACKEND_REQUIRED：CPU/alarm/dynamic/invalid 冷 backend

clock_getres syscall
  -> vkso_clock_getres_core()：范围检查 + hres/coarse 位图
     -> OK：直接 usercopy 或 NULL 成功
     -> BACKEND_REQUIRED：唯一冷 backend
```

用户 `__vkso_*` wrapper 仍是唯一 syscall fallback。产品 shared core 不知道
`k_clock`、syscall number、用户地址或 errno。

## 2. 关键语义决定

### 2.1 provider failure 不进入 `k_clock`

`UNSUPPORTED_MODE` 只可能来自合法 global hres clock。旧路径若转入
`k_clock`，其 global callback 会调用已经迁移的 `ktime_get_*()`，造成 shared
provider 的第二次无效尝试。

现在该状态直接调用 `vkso_timekeeping_get_private()`；monotonic/raw/boottime
随后根据 MM v3 mask 调用同一可映射 `vkso_time_apply_offset()`。因此没有第二
套 namespace 加法，也不重新进入 shared seq。

### 2.2 非 global clock 只分类一次 backend

`BACKEND_REQUIRED` 才调用 `clockid_to_kclock()`。CPU、alarm、dynamic/PTP
继续执行原 `k_clock` callback，保留 task lifetime、权限、RTC、FD、driver
operation 与原 errno。invalid ID 在同一出口返回 `-EINVAL`。

native time64 和 compat time32 syscall 复用相同 dispatcher，只保留各自
usercopy 格式。

## 3. 修改范围

产品源码：

- `kernel/time/posix-timers.c`
  - 新增两个统一 dispatcher；
  - 新增 provider-failure、gettime backend、getres backend 三个 cold helper；
  - native/compat syscall 删除重复 fallback 块。
- `kernel/time/timekeeping.c`
  - 将唯一 private helper命名为
    `vkso_timekeeping_get_private()`，供 syscall 冷路径与普通 kernel reader
    共用。
- `include/linux/vkso_time.h`
  - 声明该内部 kernel fallback 边界。

测试源码扩展了 encoded process/thread CPU clock、dynamic invalid FD、
ID 10、ID 12、`INT_MAX` 及对应 getres NULL/非 NULL 路径。

相对 M06：

- 产品源码：92 additions、42 deletions；
- 测试源码：80 additions；
- 没有修改 shared ABI v11、MM ABI v3、用户 wrapper 或导出 core。

## 4. 静态调用与代码生成

生产配置下：

- `__x64_sys_clock_gettime` hot：140 bytes；
- 其 cold status/backend fragment：39 bytes；
- provider-failure private helper：112 bytes；
- clock_gettime backend helper：48 bytes；
- `__x64_sys_clock_getres` hot：128 bytes；
- 其 cold fragment：22 bytes；
- clock_getres backend helper：47 bytes。

hot `clock_gettime` 汇编只有：

1. 取得 clockid、输出地址、current-MM data 与 kernel environment；
2. direct call `vkso_clock_gettime_core()`；
3. 一次 status test；
4. 成功时 `put_timespec64()`。

CPU/alarm/dynamic 的间接 `k_clock` call、provider failure 与 invalid 处理均在
`.text.unlikely`。`vkso_clock_gettime_core()` 为 267 bytes；
`vkso_clock_getres_core()` 为 42 bytes。libkernel.so 未变化，说明本阶段没有
向用户共享算法叠加新机器码。

当前对象：

- `posix-timers.o` `.text` 8828 bytes，`.text.unlikely` 331 bytes；
- `timekeeping.o` `.text` 10946 bytes，`.text.unlikely` 546 bytes；
- `vkso_time_core.o` 总计 2790 bytes。

这些是静态结构证据，不是性能测量。

## 7. 退出判断

M07 退出条件满足：

- global 成功路径不经过 `k_clock`；
- provider failure 不重试 shared core；
- CPU、alarm、dynamic/FD 与 invalid 只进入一个 backend 出口；
- native/compat 不再维护两份分派政策；
- getres 位图在无符号范围检查之后使用；
- NULL、errno、RTC、encoded CPU 与 dynamic invalid-FD 语义与 Raw 一致；
- 用户 wrapper 仍只有一个 syscall fallback。

QEMU 没有实际 PTP 设备；dynamic driver 成功 callback 将在 M09 通过测试
`posix_clock` 设备补齐。M07 已验证相同 dynamic backend 的 FD 解码与错误路径，
并且未修改其 driver callback 实现。

下一阶段 M08 清理无调用桥接、重复声明与临时结构，随后重新进行源码/机器码
归属审计。
