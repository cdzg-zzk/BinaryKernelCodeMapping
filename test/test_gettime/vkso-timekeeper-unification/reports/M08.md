# M08 阶段报告：清理、可读性与静态效率审计

## 1. 阶段结果

M08 完成了产品调用图、配置边界、用户 wrapper 和代码规模归属的人工复核。
没有改变 shared ABI v11、MM ABI v3、读取公式、发布协议或外部 ABI。

清理后的层次固定为：

```text
user public wrapper
  -> typed reader / generic dispatcher
     -> shared primitive + environment provider
  -> one cold syscall fallback

kernel syscall / ktime ABI
  -> typed reader / generic dispatcher
     -> shared primitive + kernel provider
  -> private-provider or non-global backend cold exit
```

## 2. 删除的产品冗余

### 2.1 global k_clock callback

启用 VKSO 时，dispatcher 已在 `k_clock` 前处理全部 global clock，provider
failure 也不再回到 `k_clock`。原七个 gettime 和两个 getres callback 因而
不可达。

M08 用构建边界移除这些 callback：

- `CONFIG_VKSO_TIME=y`：不生成 callback 和表项；
- `CONFIG_VKSO_TIME=n`：保留完整原实现；
- `clock_get_ktime`、set/adj、sleep、timer operation 不删除，因为 POSIX
  timer 仍调用它们。

默认 `posix-timers.o` 从 M07 的 15198 bytes 降到 14426 bytes：

| section | M07 | M08 | 变化 |
|---|---:|---:|---:|
| `.text` | 8828 | 8092 | -736 |
| `.text.unlikely` | 331 | 331 | 0 |
| object total | 15198 | 14426 | -772 |

这只是静态代码生成证据，不作为性能结果。

### 2.2 用户测试兼容 wrapper

删除了无调用的 `vkso_user_clock_gettime/getres/gettimeofday/time/getcpu`
转发函数及头文件声明。测试进程只保留一次性的
`vkso_user_wrapper_init()`；实际 public ABI 始终由 `libkernel.so` 内
`__vkso_*` 入口提供。

### 2.3 注释与临时历史

注释只保留 seq generation、原子发布、namespace 和 fallback 不变量，删除
以旧机器码布局、寄存器 spill 或某次测量为理由的开发历史约束。
`CONFIG_VKSO_TIME_TEST` probe 暂不删除：它是 M09 seq/mask/concurrency 验证
所需 T1 代码，且生产配置明确不编译。

## 3. 代码规模归属

`CODE_SIZE_MANIFEST.md` 已补充精确产品边界：

- U1/S1/K1/K2/K3/K4/B1/C1/E1/G1/P1/T1 互斥；
- `X1=0`，无 compat conversion、双 ABI 或 fallback-mode bridge；
- CONFIG=n stub、特殊 reader、关闭架构功能和测试代码单列；
- M10 只能在该人工清单内用脚本复算，不允许按整个文件猜测语义。

相对 M07，本阶段 Git churn 为 73 additions、98 deletions；其中大量
`posix-timers.c` 行是将原实现包入清晰的配置边界，不等同于产品新增功能。

## 4. 静态验证

以下对象构建通过：

- 默认 `CONFIG_TIME_NS=y`；
- `CONFIG_TIME_NS=n`；
- PVClock；
- Hyper-V；
- `CONFIG_VKSO_TIME=n` compatibility build。

符号审计确认：

- 默认对象无九个旧 global callback；
- compatibility 对象完整含有九个 callback；
- 用户 wrapper 对象只导出 `vkso_user_wrapper_init`；
- benchmark 和 ABI matrix 以 `-Wall -Wextra -Werror` 编译通过；
- `git diff --check` 通过。

M08 退出条件满足：

- 无可确认的产品死 callback；
