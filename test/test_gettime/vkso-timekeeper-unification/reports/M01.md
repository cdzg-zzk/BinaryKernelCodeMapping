# M01 阶段报告：字段、reader 与 backend 审计

## 1. 阶段目标与范围

在不修改运行时行为的前提下，为 timekeeper/VKSO 的每个字段、reader 和
clock backend 确定唯一归属，证明 ABI v11 的 cycle descriptor 设计，并划清
普通 shared reader 与特殊 reader 的边界。

本阶段产出：

- `FIELD_OWNERSHIP.md`
- `READER_CONTEXT_MATRIX.md`
- `BACKEND_SEMANTICS.md`
- `DECISIONS.md`
- 更新后的 `CODE_SIZE_MANIFEST.md`
- 本报告

## 2. 核心结论

### 2.1 cycle descriptor

全树 writer 审计证明 mono/raw 的：

- clock；
- mask；
- cycle_last；
- shift

始终成对更新且相同。只有 mono/raw mult 和 bases 不同。因此 ABI v11 使用
一个公共 descriptor，包含：

```text
clock_mode
shift
cycle_last
mask
mono_mult
raw_mult
```

不需要双 descriptor 或运行时相等判断。

### 2.2 canonical 所有权

canonical `tk_read_state` 必须嵌入 `struct timekeeper`：

- periodic tick 在 shadow instance 上计算；
- settime/suspend/switch 在 real instance 上计算；
- shared 页只保存同类型 published snapshot。

这保留 Linux shadow/real 更新顺序，同时消除 timekeeper→VKSO 的数据模型转换。

### 2.3 reader 边界

可迁移：

- 七种 global clock；
- time/gettimeofday/getres；
- 普通 process/softirq/hardirq `ktime_get_*`。

保留专用：

- fast/NMI latch；
- writer-locked/no-seq helper；
- early-boot entropy clock；
- hrtimer leap/offset helper；
- snapshot/crosstimestamp；
- arbitrary monotonic→other offset conversion。

### 2.4 backend

CPU、alarm、dynamic/PTP 和 invalid 不能塞入 shared core：

- CPU 有 task/thread、权限和采样语义；
- alarm 必须检查 RTC；
- dynamic 需要 fd/driver/lifetime；
- invalid 必须保持 Raw errno。

它们通过统一 cold dispatcher 保留。

## 3. 数据所有权变化

目标变化：

- `tkr_mono/raw` 不再是普通 reader 的两套整块模型；
- clocksource pointer 和 NTP 保留 private；
- common cycle metadata、global bases/coarse/resolution 进入 canonical；
- fast latch保留专用副本；
- MM namespace offset继续 MM_data v3；
- PV/HV页面继续 environment context；
- `monotonic_to_boot` 删除；
- ABI v10 重复 raw mode/last/shift 删除；
- v11 新增 mask；
- core fallback mode耦合在 M05 删除。

完整矩阵见 `FIELD_OWNERSHIP.md`。

## 4. 调用上下文

普通 `ktime_get()` 有约 349 个调用文件，`ktime_get_real_ts64()` 约63个，
`ktime_get_real_seconds()` 约111个。本次不修改调用者，只在 M06 保持原函数
ABI并替换为 typed root wrapper。

特殊上下文已单独列出，不以“共享一切”为目标破坏 NMI、hrtimer 或
cross timestamp 语义。完整矩阵见 `READER_CONTEXT_MATRIX.md`。

## 5. 正确性证据

- `struct timekeeper` 和 `tk_read_base` 字段逐项检查：无未分类项；
- mono/raw 四个公共字段全树赋值点检查：无不对称写点；
- `timekeeping_update()` 所有调用事件检查：init/tick/NTP/settime/clock switch/
  suspend/resume/sleep/leap均覆盖；
- MM_data exec/fork/setns 生命周期检查：无并发 offset writer，v3无需 seq；
- `posix_clocks[]`、negative clockid、CPU/alarm/dynamic 后端检查：语义已入表；
- public wrapper、kernel syscall和 core fallback 路径检查：重复政策已标记；
- 本阶段没有运行时代码变化，因此 M00 功能基线保持。

## 6. 静态性能模型

本阶段不改机器码。为后续锁定的静态目标：

- shared descriptor 删除一份 raw mode/last/shift，新增一个必要 mask；
- root kernel reader不支付 MM_data 检查；
- typed global reader不经过 generic dispatcher；
- shared core不读取 fallback mode；
- user/kernel只复制最小 provider，不复制算法；
- shared seq奇数区间不执行 derived-base计算；
- event timezone不随 periodic tick重写。

这些是设计预期，不是裸机性能结论。

## 7. 代码规模

本阶段只增加审计文档，不计产品 SLOC。已经识别的最终删除项：

- 60 SLOC compat adapter；
- `monotonic_to_boot` 字段和维护；
- ABI v10 raw descriptor重复字段和发布；
- core fallback-mode政策；
- 迁移后旧普通 global reader重复算法；
- 多层仅转发 wrapper。

必要保留项已从“重复代码”中剔除：fast/NMI、hrtimer、snapshot、CPU/alarm/
dynamic backend和 private NTP。

## 8. 风险与 M02 入口

M02 需要验证：

- v11 首个 cache line 是否容纳 header+common descriptor+realtime seconds/base；
- monotonic最多多一个 cache line；
- raw 独立对齐；
- kernel producer、libkernel.so wrapper和 tests在一次提交中同步 ABI；
- v10 不形成兼容双路径；
- `time()` 64位 seconds对齐；
- v11 新 mask 不改变 TSC 正常语义。

M01 已满足“每个字段和 reader 有唯一归属、未审计对象不得迁移”的退出条件，
可以进入 M02。
