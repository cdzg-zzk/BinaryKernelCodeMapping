# M06 阶段报告：普通 kernel reader 统一

## 1. 阶段结果

M06 已将 M01 审计为普通上下文安全的 global-time kernel reader 接入
canonical shared core。调用者、函数名、参数、返回类型及既有 EXPORT 均未改变：

```text
ktime_get_* public ABI
  -> clock-specific typed root reader
     -> shared seq / cycles / arithmetic core
  -> unsupported mode only: one private cold compatibility helper
```

kernel root reader 不传 MM_data、不读取 namespace mask，也不经过
`vkso_clock_gettime_core()` generic clock-ID dispatcher。

## 2. 已迁移 reader

以下普通 API 已使用 typed root path：

- `ktime_get()`、`ktime_get_ts64()`；
- `ktime_get_real_ts64()`；
- `ktime_get_raw()`、`ktime_get_raw_ts64()`；
- `ktime_get_with_offset()` 的 realtime、boottime、TAI；
- realtime/monotonic/boottime/TAI coarse 组；
- `ktime_get_resolution_ns()`；
- `ktime_get_seconds()`、`ktime_get_real_seconds()`。

外部调用者继续使用原 API，未批量修改任何子系统。

typed hres reader 现在只接收 result 与 environment context，typed coarse reader
只接收 result。MM_data 已从所有 typed reader 签名和机器码中删除。

## 3. Namespace 与共享公式

typed reader 永远返回 root-namespace time。per-MM offset 被移动到两个真正需要它
的 public 边界：

- syscall generic core 在 typed 读取成功后检查 MM mask；
- user entry 在 typed 读取成功后检查绑定的 MM mask。

offset 加法与归一化仍只有一份 `vkso_time_apply_offset()` 共享 core 实现；
user assembly 只做 mask 检查并在非 root namespace tail-jump 到该公式，没有
重写时间算法。

因此：

- kernel 普通 reader 没有 MM 地址、NULL 或 mask 成本；
- user/syscall 的 time namespace 语义保持；
- root 与 context 的职责边界可静态审计。

## 4. Coarse 与 private compatibility

ABI v11 直接发布 realtime/monotonic coarse。kernel-only boottime/TAI coarse
由同一 shared generation 中的 coarse value 与 canonical hres base 差值派生，
不重新访问 private timekeeper。

任意 Linux clocksource 仍必须支持 kernel reader。若当前 mode 不能由共享
TSC/PV/HV provider 表示，普通 reader 进入唯一的
`timekeeping_get_private(clock_id, coarse, result)` cold helper。该 helper
集中保留现有动态 clocksource read 语义，不是第二套常用 reader：

- 所有 caller branch 均以 unsupported 为 unlikely；
- helper 位于 `.text.unlikely`；
- normal TSC/PV/HV 不进入它；
- early/unsupported mode 不会使 public `ktime_get_*` 失败。

## 5. 明确保留的特殊路径

M06 没有改动：

- `ktime_get_*_fast_ns()` 与 `ktime_get_fast_timestamps()`；
- `__ktime_get_real_seconds()` writer-held reader；
- `ktime_get_update_offsets_now()` hrtimer helper；
- `ktime_get_snapshot()` 与 cross timestamp；
- `ktime_mono_to_any()` 历史值转换；
- producer、suspend/early clocksource 与 writer-locked helper。

这些路径仍使用 private/latch 语义，避免 NMI 中断 shared writer 后等待同一个
奇数 seq。

## 6. 静态路径与代码量

`timekeeping.o` 的普通 reader 只引用 clock-specific symbol；没有
`vkso_clock_gettime_core`、MM_data 或 current-MM dependency。以
`ktime_get()` 为例，成功路径是一次 direct call
`vkso_clock_gettime_monotonic`，失败分支进入 `.cold`。

当前生产目标文件：

- `timekeeping.o` text：13387 bytes；
- `vkso_time_core.o` text：2744 bytes；
- 集中的 private cold helper：303 bytes；
- `ktime_get()` hot symbol：134 bytes；
- `ktime_get_real_ts64()` hot symbol：56 bytes。

相对 M05 的产品源码 diff 为 389 additions、211 deletions，测试增加 55 行。
其中 `timekeeping.c` 删除 118 行旧普通 reader 公式、增加 130 行 typed adapter、
derived coarse 与单一 cold compatibility helper，净增加 12 行。

整体净增长主要来自 typed ABI 声明、root/MM 边界和 user entry 的显式 offset
注入，并非另一份 global-time 算法。该增长不是最终代码量结论；M08 必须在
不恢复 MM 热依赖和不降低可读性的前提下合并重复声明/adapter。M10 才进行
Raw/VKSO 最终同边界统计。

本阶段不作裸机性能结论。静态上，private fallback 已进入 cold section；
libkernel 的三个 namespace-aware typed reader各从 0x150 缩小为 0x110，
public `__vkso_clock_gettime` 因承担 MM policy 从 0xd8 增为 0x142。

## 8. 退出判断

M06 退出条件满足：

- 普通 kernel reader 是 clock-specific typed root adapter；
- root path 不访问 MM_data，不经过 generic dispatcher；
- 特殊/NMI/writer-held 路径逐项保留；
- unsupported mode 由一个 cold private helper 完整兜底；
- 模块和子系统调用方式未改变；
- 配置矩阵、kernel selftest 和 Raw/VKSO QEMU 语义均通过。

下一阶段 M07 将统一 clock dispatcher/backend 边界，消除 syscall wrapper、
generic core 与 POSIX `k_clock` 之间重复的 clock 分类和 fallback 判断。
