# M04 阶段报告：canonical state 短发布

## 1. 阶段结果

M04 已删除最后的同类型 bridge。`timekeeping_update()` 在完成 canonical
`tk_read_state` 后，将其地址直接传给 publisher；publisher 不再接收
`struct timekeeper`，不再构造栈上 snapshot，也不再执行任何跨模型准备。

更新路径现在明确分为：

1. producer 在既有 timekeeper writer 同步内完成复杂计算；
2. canonical state 已完整且自洽；
3. shared seq 置为奇数；
4. publisher 发布固定宽度 scalar payload；
5. 写屏障后 shared seq 置为偶数。

## 2. 发布协议

周期发布包含 21 个固定宽度字段，共 148 bytes：

- cycle descriptor：mode、shift、cycle_last、mask、mono/raw mult；
- realtime、monotonic、boottime、TAI 和 raw base；
- realtime/monotonic coarse；
- hrtimer resolution。

以下字段不在周期发布中重复写入：

- `seq` 和 ABI header 由协议本身管理；
- `timezone` 只在 timezone 事件发生时发布；
- reserved 字段不参与功能状态。

seq 奇数区间内没有除法、循环、函数调用、clocksource 指针访问、namespace
处理或另一种数据模型的转换。`time()` 使用的 realtime seconds 仍以自然对齐
的 64-bit `WRITE_ONCE` 单次发布。

## 3. Memory ordering

写侧协议保持：

```text
seq = odd
smp_wmb()
scalar payload stores
smp_wmb()
seq = even
```

读侧继续用 acquire load 读取起始 seq，并在复制完需要字段后以 acquire fence
和第二次 seq 检查确认快照属于同一代。reader 只会看到完整旧代、重试或完整
新代，不会接受 torn snapshot。

shared 页仍只包含 ABI v11 固定宽度数据，不含 private 指针、锁或相邻
timekeeper 内容。

## 4. 静态性能模型

`vkso_time_publish()` 的当前目标文件结果：

- 符号大小：258 bytes；
- `vkso_time.o` `.text`：349 bytes；
- odd window：直接 load/store 与必要 barrier，不含 call、division 或临时
  整页复制；
- 周期 payload：148 bytes，而不是复制完整 shared 页。

源代码产品 diff（相对 M03）为 28 additions、52 deletions。主要删除项是
19-line compat header、栈上 snapshot 和接收 `struct timekeeper` 的转换边界。
M04 不声称真实性能提升；该结构只证明复杂 producer 工作没有被放进 shared
seq 冲突窗口。

## 6. 退出判断

M04 退出条件满足：

- publisher 只接收 canonical `tk_read_state`；
- `vkso_time_compat.h` 与 compat prepare 完全删除；
- shared seq 奇数区间只包含固定 payload 发布；
- timezone 等事件字段不随 tick 重写；
- ABI、配置矩阵和 QEMU 语义均通过。

下一阶段 M05 将把 shared core 改为纯读取/计算组件，分离 environment
provider，并把 syscall/backend fallback 政策移到 public 边界。
