# M03 阶段报告：canonical state 进入 timekeeper producer

## 1. 阶段结果

M03 已把 ABI v11 的 `vkso_read_state` 嵌入 real 与 shadow
`struct timekeeper`，并将它确立为普通 global-time reader 的 canonical 状态。
cycle descriptor、七种 global clock base、coarse、resolution均由
timekeeping producer在持有 `timekeeper_lock` 时完成。

M02 的逐字段 `timekeeper -> vkso_shared_data` 派生转换已删除。M03 只保留一个
临时的同类型结构赋值 bridge，使旧 publisher签名继续工作；M04将直接传递
`tk->read_state`并删除该 bridge。

## 2. Producer 所有权

`timekeeping_update()` 的顺序现在是：

1. 处理 NTP clear与leap state；
2. 更新既有 private/special-reader ktime数据；
3. `tk_update_read_state()` 完成 canonical reader state；
4. 更新 PV clock GTOD；
5. 更新 fast/NMI latch；
6. 发布 canonical state；
7. 按原顺序 mirror real/shadow。

canonical字段来源：

| 字段组 | Producer source | 所有权结果 |
|---|---|---|
| mode/shift/last/mask | active `tkr_mono` | 单一公共 descriptor |
| mono/raw mult | NTP-adjusted mono与raw private state | 分别保存 |
| realtime | xtime sec + shifted nsec | canonical base |
| monotonic | realtime + wall-to-monotonic | canonical base |
| boottime | canonical monotonic + preserved sleep offset | canonical base |
| TAI | canonical realtime + TAI offset | canonical base |
| raw | raw sec + shifted raw nsec | canonical base |
| coarse | 已归一化 canonical realtime/monotonic | canonical value |
| resolution | hrtimer producer-visible resolution | canonical value |

普通 reader在后续M05/M06只读取canonical。`tkr_mono/raw`暂时保留，因为
fast/NMI、crosstimestamp、clocksource identity和M06前的既有kernel reader仍需
private/special表示；它们不再被shared publisher重新解释。

## 3. Boottime 设计

旧 `monotonic_to_boot` 是仅为每次vDSO/VKSO发布准备的第二份timespec offset，
现已删除。

为避免用 `ktime_to_timespec64(offs_boot)` 在每个tick引入64-bit除法：

- normal update从旧canonical boottime/monotonic base的差值恢复sleep offset；
- clocksource shift变化时先按旧shift恢复整数纳秒offset，再按新shift构造base；
- suspend/sleeptime注入是罕见事件，直接推进canonical boottime base；
- `offs_boot`继续服务fast/snapshot等必要kernel接口。

因此，周期路径没有新增division，boottime仍只有一个reader-ready表示。

## 4. Writer 事件覆盖

所有目标事件最终进入 `timekeeping_update()`，因此在seq发布前完成canonical：

- boot initialization；
- periodic tick和frequency/NTP adjustment；
- settimeofday与time injection；
- leap second和TAI offset；
- clocksource switch；
- suspend/resume与sleeptime injection；
- warp clock；
- shadow→real、real→shadow mirror。

timezone仍是独立事件型字段：`sys_tz`改变时直接更新shared event field，不随
periodic publisher重写。它不属于tick canonical payload的source-of-truth。

## 5. 特殊 reader 边界

本阶段未把以下路径强制改成shared seq reader：

- fast/NMI latch；
- writer-locked helper；
- crosstimestamp和clocksource identity；
- hrtimer leap/offset helper；
- early boot entropy clock。

这符合M01矩阵；它们将在M06继续保持专用，避免NMI打断writer后的seq自等待。

## 7. 代码规模纪律

本阶段产品diff为113 additions、75 deletions，其中：

- 删除旧60余行跨数据模型compat派生；
- 新增producer canonical finalization与boottime offset维护；
- `monotonic_to_boot`字段及更新删除；
- 临时bridge只有一次同类型赋值，M04必须删除，不进入最终X1。

每个timekeeper实例新增160-byte canonical state并删除16-byte
`monotonic_to_boot`，净增144 bytes；real与shadow合计净增288 bytes。这是
canonical ownership的显式状态成本，不隐藏为代码节省。M04会删除额外栈
snapshot，M08/M10再审计普通reader迁移后private字段是否还能缩减。

## 8. 退出判断

M03退出条件满足：

- real/shadow各自拥有同类型canonical generation；
- 所有global clock和cycle字段有唯一producer finalization点；
- NTP/settime/TAI/leap/suspend/switch事件均覆盖；
- 旧逐字段compat派生消失；
- `monotonic_to_boot`消失且周期路径无新增division；
- 特殊reader边界保持；
- 构建与QEMU功能语义通过。

下一阶段M04删除临时同类型bridge，让publisher只接收
`const struct vkso_read_state *`，并审计seq奇数窗口和实际发布字节。
